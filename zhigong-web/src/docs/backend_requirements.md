# 后端支持需求文档

## 1. 概述

本文档定义了后端需要支持的分类功能需求，包括数据库字段设计、API接口调整和数据处理逻辑。

## 2. 数据库设计

### 2.1 新增分类字段

在政务信息表中新增一个分类字段，用于存储爬虫爬取时标记的分类信息：

| 字段名 | 数据类型 | 长度 | 描述 |
|--------|----------|------|------|
| `category` | VARCHAR | 50 | 分类名称，如：政策法规、人事信息、规划计划、公考资讯、招标采购 |

### 2.2 字段约束

- 允许为NULL，兼容旧数据
- 建议添加索引，优化查询性能
- 分类名称必须与前端页面的分类名称保持一致

## 3. API接口调整

### 3.1 列表查询接口

**接口地址**：`GET /api/public-info/list`

**新增参数**：

| 参数名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| `category` | String | 否 | 分类名称，用于筛选特定分类的数据 |

**参数说明**：
- 当传入`category`参数时，只返回该分类下的数据
- 当未传入`category`参数时，返回所有分类的数据
- 分类名称必须与数据库中的`category`字段值完全匹配

**响应格式**：
```json
{
  "data": [...],     // 数据列表
  "total": 100,      // 总条数
  "page": 0,         // 当前页码
  "size": 20         // 每页条数
}
```

### 3.2 热门信息接口

**接口地址**：`GET /api/public-info/hot`

**新增参数**：

| 参数名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| `category` | String | 否 | 分类名称，用于筛选特定分类的热门数据 |

**参数说明**：
- 当传入`category`参数时，只返回该分类下的热门数据
- 当未传入`category`参数时，返回所有分类的热门数据

**响应格式**：
```json
{
  "data": [...],     // 数据列表
  "total": 100,      // 总条数
  "page": 0,         // 当前页码
  "size": 20         // 每页条数
}
```

## 4. 数据处理逻辑

### 4.1 分类数据查询

- 当请求中包含`category`参数时，使用`WHERE category = ?`条件查询
- 当请求中同时包含`category`和其他查询条件（如`q`、`region`等）时，使用`AND`条件组合
- 确保分类查询的性能，建议为`category`字段添加索引

### 4.2 兼容旧数据

- 对于没有`category`字段值的旧数据，不影响查询结果
- 当查询特定分类时，旧数据不会被包含在结果中
- 建议在后台提供手动补充分类的功能，逐步完善旧数据的分类信息

### 4.3 分页处理

- 分类查询支持分页，与现有分页逻辑保持一致
- 分页参数：`page`（页码，0-based）、`size`（每页条数）
- 响应中包含正确的`total`、`page`、`size`字段

## 5. 数据源支持

- 分类查询同时支持Redis和MySQL数据源
- Redis数据源需要支持按`category`参数进行缓存
- 缓存key需要包含`category`参数，确保不同分类的缓存隔离

## 6. 错误处理

- 当传入无效的分类名称时，返回空数据列表，不报错
- 当数据库查询出错时，返回标准的错误响应格式

## 7. 性能要求

- 分类查询的响应时间应控制在500ms以内
- 支持高并发查询，建议使用缓存优化

## 8. 测试要求

- 测试不同分类的查询结果是否正确
- 测试分类查询与其他查询条件的组合结果
- 测试分页功能在分类查询中的正确性
- 测试Redis和MySQL数据源的分类查询结果一致性
