# 前端对接指南 (Frontend Integration Guide)

本文档旨在指导前端开发人员如何正确对接后端API，特别是针对**热门数据**和**分类数据**的获取。

## 1. 核心对接原则

后端数据存储采用 **Redis + MySQL** 混合架构：
- **Redis**: 存储最新、最热的数据（如首页热门列表）。
- **MySQL**: 存储全量归档数据（如历史搜索、特定分类查询）。

前端在请求数据时，需根据业务场景选择正确的接口。

## 2. 接口调用指南

### 2.1 首页热门信息 (Hot Info)

首页展示的"最新动态"或"热门资讯"，**必须**优先从 Redis 获取，以保证高性能和实时性。

*   **接口地址**: `GET /public-info/hot/list`
*   **数据来源**: Redis (Key: `gov:data:hot`) -> 降级到 MySQL
*   **请求参数**: 无
*   **响应示例**:
    ```json
    {
      "code": 200,
      "message": "success",
      "data": [
        {
          "dataId": "5320d15d...",
          "title": "海南省2025年度公开遴选公务员公告",
          "category": "招考招聘",
          "publishTime": "2025-01-15T00:00:00+08:00",
          "isNew": 1,
          ...
        },
        ... (Top 20 items)
      ]
    }
    ```

### 2.2 分类专区数据 (Category Data)

当用户点击具体栏目（如"招考招聘"、"政策解读"）时，**必须**使用分类查询接口，该接口从 MySQL 中检索数据。

*   **接口地址**: `GET /public-info/category/data`
*   **数据来源**: MySQL (`public_info` 表 `category` 字段)
*   **请求参数**:
    *   `categoryTag`: **必填**。分类标签名称 (与 `category` 字段匹配)。
        *   示例值: `招考招聘`, `人事任免`, `干部任前公示`, `政策解读` 等。
    *   `page`: 页码 (默认 1)
    *   `size`: 每页条数 (默认 20)
*   **响应示例**:
    ```json
    {
      "code": 200,
      "message": "success",
      "data": {
        "total": 150,
        "page": 1,
        "size": 20,
        "list": [
            { "title": "...", "category": "招考招聘", ... }
        ]
      }
    }
    ```

### 2.3 获取所有可用分类

如果前端需要动态生成导航栏菜单，可调用此接口获取系统当前支持的所有分类标签。

*   **接口地址**: `GET /public-info/category/list`
*   **响应**: `["招考招聘", "人事任免", ...]`

## 3. 字段匹配说明

前端展示时，请注意以下字段映射：

| 后端字段 (`PublicInfo`) | 前端展示含义 | 说明 |
| :--- | :--- | :--- |
| `dataId` | 唯一ID | 用于跳转详情页，路由建议 `/detail/{dataId}` |
| `title` | 标题 | 列表页主要展示内容 |
| `category` | **分类标签** | 用于显示标签角标，也是分类查询的 Key |
| `publishTime` | 发布时间 | 格式通常为 ISO8601，前端需格式化为 `YYYY-MM-DD` |
| `sourceOrg` | 发布部门 | 来源单位 |
| `attachments` | 附件列表 | 数组，包含 `name` 和 `url` (MinIO 链接) |

## 4. 常见问题 (FAQ)

**Q: 为什么首页数据和分类列表数据可能不完全一致？**
A: 首页数据来自 Redis 缓存的最新爬取流，更新频率极高（接近实时）。分类列表查询 MySQL，依赖后端定时同步任务（通常每 5-10 分钟同步一次）。

**Q: 如何处理 `category` 不存在的情况？**
A: 请确保请求的 `categoryTag` 与后端 `category/list` 返回的列表一致。如果需要新增分类，需联系后端在配置表中添加。
