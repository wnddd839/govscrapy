# 政务公开信息整合平台爬虫项目优化方案

## 一、项目现状分析

当前爬虫项目与优化计划的主要差距：

1. **Redis配置不一致**：当前使用db=0，需改为1
2. **数据结构不匹配**：字段命名、Redis键名与后端规范不符
3. **分类逻辑硬编码**：未实现可配置的URL规则+关键词分类
4. **爬取规则不灵活**：目标网站、解析规则硬编码
5. **反爬策略不完善**：缺少随机User-Agent、IP代理池等
6. **缺少定时调度**：未实现APScheduler定时任务

## 二、优化实施计划

### 1. 配置文件优化

**目标**：实现灵活的配置管理，支持动态调整爬取规则和分类

**实施内容**：

* 创建`config/`目录，包含三个配置文件：

  * `redis_config.yml`：Redis连接配置（db改为1）

  * `crawl_rules.yml`：按网站维度配置爬取规则

  * `category_config.yml`：分类规则配置

* 修改`settings.py`，加载配置文件

### 2. 数据模型优化

**目标**：与后端PublicInfo实体类字段完全对齐

**实施内容**：

* 修改`items.py`，使用驼峰命名法

* 确保所有字段与后端要求一致：

  * dataId（UUID，32位无横线）

  * title（String(255)）

  * content（Text）

  * publishTime（YYYY-MM-DD HH:mm:ss）

  * sourceUrl（String(512)）

  * sourceWebsite（String(100)）

  * publishDept（String(100)）

  * category（String(50)）

  * crawlTime（YYYY-MM-DD HH:mm:ss）

  * isNew（固定为1）

### 3. Redis数据结构优化

**目标**：严格遵循后端Redis存储规范

**实施内容**：

* 修改`pipelines.py`，实现：

  * Hash存储：`gov:data:{dataId}`（24小时TTL）

  * 待同步集合：`gov:data:new`（Sorted Set）

  * 热门数据集合：`gov:data:hot`（Sorted Set，保留最新100条）

* 使用驼峰命名法存储字段

### 4. 分类逻辑优化

**目标**：实现URL规则优先，关键词兜底的分类匹配

**实施内容**：

* 将分类规则从代码分离到`category_config.yml`

* 实现分类匹配逻辑：

  1. URL规则匹配（如`/rsxx/`→"人事信息"）
  2. 关键词匹配（如标题含"决算"→"财政决算"）

* 确保分类标签与后端gov\_category\_config表一致

### 5. 爬取规则优化

**目标**：实现基于配置的动态爬取

**实施内容**：

* 将爬取规则从代码分离到`crawl_rules.yml`

* 支持配置：网站名称、域名、列表页URL模板、详情页解析规则、爬取间隔、启用状态

* 实现基于配置的分页爬取逻辑

### 6. 反爬策略优化

**目标**：提高爬虫稳定性，避免被反爬

**实施内容**：

* 添加随机User-Agent中间件（fake-useragent）

* 添加IP代理池支持

* 添加请求频率限制

* 添加重试机制

### 7. 数据去重优化

**目标**：避免重复爬取和写入

**实施内容**：

* 实现基于"title+publishTime"的指纹生成

* 使用Redis集合存储已爬取指纹

* 避免重复写入Redis

### 8. 定时调度实现

**目标**：实现自动定时爬取

**实施内容**：

* 创建`scheduler/`目录

* 实现APScheduler定时调度，支持cron表达式

* 支持配置爬取频率

## 三、项目结构优化

优化后的项目结构：

```
gov_data/
├── config/                  # 配置目录
│   ├── redis_config.yml     # Redis配置
│   ├── crawl_rules.yml      # 爬取规则配置
│   └── category_config.yml  # 分类规则配置
├── gov_data/               # 核心代码
│   ├── items.py            # 数据模型
│   ├── pipelines.py        # 数据处理
│   ├── middlewares.py      # 中间件
│   ├── settings.py         # 项目配置
│   └── spiders/            # 爬虫
├── scheduler/              # 定时调度
│   └── scheduler.py        # 调度入口
└── requirements.txt        # 依赖清单
```

## 四、实施顺序

1. 配置文件编写（Redis、爬取规则、分类规则）
2. 数据模型优化（items.py）
3. Redis数据结构优化（pipelines.py）
4. 分类逻辑优化（pipelines.py + category\_config.yml）
5. 爬取规则优化（spiders + crawl\_rules.yml）
6. 反爬策略优化（middlewares.py）
7. 数据去重优化（pipelines.py）
8. 定时调度实现（scheduler/）
9. 与后端联调

## 五、预期效果

1. **标准化对接**：与后端Redis完全兼容，数据格式一致
2. **自动化分类**：基于URL规则+关键词的自动分类，准确率≥95%
3. **灵活配置**：支持动态调整爬取规则和分类，无需修改代码
4. **稳定可靠**：完善的反爬策略，数据去重，定时调度
5. **易于扩展**：新增网站或分类只需修改配置文件
